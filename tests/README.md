# Detection Pack Tests

Sample artifacts for validating that rules in this pack fire correctly. Each test file represents either a malicious indicator (should trigger detection) or a benign control (should NOT trigger).

## Structure

```
tests/
├── README.md                              (this file)
├── pickle_test_malicious.pkl              (binary — triggers pickle YARA rules)
├── pickle_test_benign.pkl                 (binary — should NOT trigger)
├── mcp_config_poisoned.json               (triggers MCP tool poisoning YARA)
├── mcp_config_benign.json                 (should NOT trigger)
├── rag_document_hidden_text.html          (triggers RAG hidden-text YARA)
├── rag_document_benign.html               (should NOT trigger)
├── copilot_rules_backdoored.md            (triggers Rules File Backdoor YARA)
├── sample_logs/
│   ├── azure_openai_injection.json        (Azure diagnostic log — triggers Azure Sigma rule)
│   ├── bedrock_high_tokens.json           (Bedrock invocation log — triggers Bedrock Sigma rule)
│   ├── m365_copilot_sensitive.json        (Purview audit log — triggers M365 Copilot Sigma rule)
│   ├── ray_jobs_api_rce.pcap.txt          (HTTP request — triggers Ray Suricata)
│   └── camoleak_pixel_burst.pcap.txt      (HTTP burst — triggers CamoLeak Suricata)
└── validate.sh                            (smoke-test runner script)
```

## How to validate

### YARA rules
```bash
# All rules in a category against a single test file
yara -r ../03-model-supply-chain/pickle_malicious_opcodes.yar pickle_test_malicious.pkl
# Should print at least one rule match.

yara -r ../03-model-supply-chain/pickle_malicious_opcodes.yar pickle_test_benign.pkl
# Should print nothing.
```

### Sigma rules
Convert to your target backend, then replay the sample event:
```bash
sigma convert -t lucene ../02-mcp-attacks/mcp_config_tampering.yml
# Paste output query into your SIEM against an index containing the sample event
```

### Suricata rules
Replay the captured request via curl against a Suricata sensor with the rules loaded, or use `suricata -r` against a pcap.

### Cloud log samples (Sigma rules)
Ingest the JSON sample into any SIEM as a test event, then convert the Sigma rule to the target backend and replay the detection against the ingested sample.

## Important note on pickle test files

The "malicious" pickle test contains a real pickle bytecode payload that, if loaded with `pickle.load()`, will execute `print("YARA test - if you see this, do not run untrusted pickles")`. It is harmless but is intentionally crafted to be detected. **Do not load any pickle file with `pickle.load()` unless you have inspected its bytecode.**

## Building / regenerating tests

The pickle test files are generated by `generate_test_pickles.py` (committed alongside). The script is provided so that the binary artifacts can be re-created from source — never trust pre-built pickle binaries from a Git repo without inspection.
